# 模拟拼多多同步

1. 登录云端账号，打开「平台连接」。可以为现有拼多多店铺添加模拟连接，或创建独立的「月明净拼多多旗舰店（模拟）」。
2. 在「同步任务」依次执行商品、订单、退款同步。Mock Adapter 提供三个模拟商品、九笔初始订单和一笔部分退款。第二次运行只获取游标后的变化。
3. 在「平台连接」可新增模拟订单、更新订单状态、添加退款、选择故障场景、绑定或解除 SKU，并重置该连接的模拟源数据。状态变化后需再次运行相应同步。
4. 每个批次通过 PostgreSQL 函数在同一事务中写入记录和游标；外部 ID 唯一键阻止重复订单与退款。同一连接同一时间只允许一个运行中任务。失败可在「同步任务」重试；已经提交的批次不会重读。
5. 模拟连接数据属于对应店铺。RLS 限制读取；Viewer 只读，Editor 可运行模拟同步和管理映射，Owner/Admin 可创建连接、切换后台调度和重置。

## 经营口径

- 模拟订单按店铺时区的下单日期汇总。取消订单不计销售额；成功退款才冲减净销售额。
- 当天已有手工或 CSV 日汇总时，以该日汇总为准，不再叠加模拟订单和退款。这样避免重复销售额，但需要用户确认手工数据是否覆盖当天所有订单。
- 模拟订单有 SKU 映射且当日有生效成本版本时，按商品数量估算成本；映射或成本不齐时标为「数据不完整」。历史成本不会被同步任务覆盖。
- 广告 ROAS 继续只使用人工录入的广告归因成交额与广告消耗。普通模拟订单不会进入广告归因收入。
- 页面显示的模拟订单、退款和销售额均为演示数据，不能用于真实经营决策。

## 定时任务

`vercel.json` 每天 00:00 UTC（北京时间 08:00）请求 `/api/cron/mock-sync`，只处理勾选自动同步的模拟连接，依次同步商品、订单和退款；不会调用官方接口。部署环境需设置仅服务端的 `CRON_SECRET` 和 `SUPABASE_SECRET_KEY`。Cron 路由校验 `Authorization: Bearer <CRON_SECRET>`。不要使用 `NEXT_PUBLIC_` 前缀，也不要把 Secret Key 放入 GitHub。

Vercel 套餐对 Cron 频率与函数时长可能有限制；当前每天一次、每次最多处理 10 个连接。超过规模后应改为队列分片调度。Codespaces 预览服务器停止时不会运行此 Cron。未部署或未设置两个服务端密钥时，勾选开关只记录意愿，定时同步不会启动；手动同步仍可用。

## 测试与部署

`npm run test` 使用隔离 PGlite 执行迁移、约束、RLS 和模拟同步测试。真实 Supabase 项目的数据库迁移应先在测试项目验证，再按文件名顺序应用 `supabase/migrations/202610180001_mock_sync.sql` 与 `202610180002_refund_guard.sql`。请勿在生产库运行 `supabase/tests/mock_sync.sql`，它是测试夹具。
